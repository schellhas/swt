Die Welt der Softwaretechnik

Taxonomie aus VL03 – die roten Begriffe zeigen, wo deine Themen im Baum stehen.

  • Welt der Problemstellungen
    • Produktprobleme (Komplexität)
      • Anforderungsprobleme → Problemraum (WAS) ← ① Anforderungen / Anwendungsfälle
      • Entwurfsprobleme → Lösungsraum (WIE) ← ② Entwurfsmuster ③ UML / OCL ⑥ Architekturstile
    • Prozessprobleme (psycho-sozial)
      • Kognitive Beschränkungen
      • Mängel der Urteilskraft ← ⑤ Prozessmodelle / agil / konventionell
      • Kommunikation, Koordination ← ⑤ Prozessmodelle / agil / konventionell
      • Gruppendynamik
      • Verborgene Ziele
      • Fehler (Fehler → Defekt → Versagen) ← ④ QA / Tests
  • Welt der Lösungsansätze – Technische Ansätze („hart“)
    • Abstraktion
    • Wiederverwendung ← ② Entwurfsmuster(abgeleitet) ⑥ Architekturstile(abgeleitet)
    • Automatisierung ← ④ Testautomatisierung(abgeleitet)
  • Welt der Lösungsansätze – Methodische Ansätze („weich“)
    • Anforderungsermittlung ← ① Anforderungen / Anwendungsfälle ③ UML
      VL05 Anforderungen · VL06 Use Cases · VL07 Objektmodell (Klassendiagramm) · VL08 dynamisches Modell (Sequenz-, Zustandsdiagramm)
    • Entwurf ← ② Entwurfsmuster ③ OCL ⑥ Architekturstile
      VL09 Architektur · VL10 Modularisierung · VL11/12 Entwurfsmuster · VL13 Schnittstellenspezifikation (OCL, Object Design)
    • Qualitätssicherung ← ④ QA / Tests
      • analytisch: dynamisch (Tests), statisch (Durchsichten)
      • konstruktiv: Test-/Durchsicht-, Prozess-, Projekt-/Risikomanagement
    • Projektmanagement ← ⑤ Softwareprozesse / Prozessmodelle / agil / konventionell(teils abgeleitet)
„(abgeleitet)“ = nicht ausdrücklich in den Folien belegt. UML hat keinen eigenen Ast – es ist die Notation für Anforderungsermittlung und Entwurf.
