DIE WELT DER SOFTWARETECHNIK
│
├─ WELT DER PROBLEMSTELLUNGEN
│  ├─ Produktprobleme (Komplexität)
│  │   ├─ Anforderungsprobleme → Problemraum (WAS)          ← löst: ① Anforderungen / Anwendungsfälle
│  │   │     (Domäne komplex, widersprüchliche Wünsche, Änderungen)
│  │   └─ Entwurfsprobleme → Lösungsraum (WIE)              ← lösen: ② Entwurfsmuster, ③ UML/OCL, ⑥ Architekturstile
│  └─ Prozessprobleme (psycho-sozial)
│      ├─ Kognitive Beschränkungen
│      ├─ Mängel der Urteilskraft                            ← betrifft: ⑤ Prozessmodelle / agil / konventionell
│      ├─ Kommunikation, Koordination                        ← betrifft: ⑤ Prozessmodelle / agil / konventionell
│      ├─ Gruppendynamik
│      ├─ Verborgene Ziele
│      └─ Fehler (Fehler → Defekt → Versagen)                ← löst: ④ QA / Tests
│
└─ WELT DER LÖSUNGSANSÄTZE
   ├─ TECHNISCHE ANSÄTZE („hart“)
   │   ├─ Abstraktion
   │   ├─ Wiederverwendung                                   ← ② Entwurfsmuster (abgeleitet), ⑥ Architekturstile (abgeleitet)
   │   └─ Automatisierung                                    ← ④ Testautomatisierung (abgeleitet)
   │
   └─ METHODISCHE ANSÄTZE („weich“)
       ├─ ANFORDERUNGSERMITTLUNG                            ← ① Anforderungen / Anwendungsfälle
       │     VL05 Anforderungen, VL06 Use Cases,               ③ UML (Klassen-, Sequenz-, Zustandsdiagramm)
       │     VL07 Objektmodell, VL08 dynamisches Modell
       ├─ ENTWURF                                           ← ② Entwurfsmuster (VL11/12)
       │     Architektur, Modularisierung,                     ③ OCL (VL13, Object design)
       │     Wiederverwendung, Dokumentation                   ⑥ Architekturstile (VL09)
       ├─ QUALITÄTSSICHERUNG                                ← ④ QA / Tests
       │     ├─ analytisch: dynamisch (Tests), statisch (Durchsichten)
       │     └─ konstruktiv: Test-/Durchsicht-, Prozess-, Projekt-/Risikomanagement
       └─ PROJEKTMANAGEMENT                                 ← ⑤ Softwareprozesse, Prozessmodelle, agil / konventionell (teils abgeleitet)

rot = deine Begriffe · grau „abgeleitet“ = nicht ausdrücklich in den Folien belegt · UML hat keinen eigenen Ast (Notation für Anforderungsermittlung und Entwurf)
