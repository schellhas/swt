Prio-Liste: Was zuerst lernen?

Gewichtung aus uebersicht.txt (Umfang/explizite Hinweise im Original) + Abdeckung in ub/ (mehrfach behandelte Themen = wahrscheinlicher prüfungsrelevant).  ← zurück zur Übersicht

Abgleich mit der Praxis: Laut Altklausur-Erfahrungsbericht eines Kommilitonen lag der größte Punkteanteil in der tatsächlichen Klausur auf Anforderungsanalyse, Anwendungsfällen, UML und OCL (Transferaufgaben) — nicht auf Prozessmodellen/Entwurfsmustern. Diese Liste hier basiert auf dem Umfang in uebersicht.txt; für die konkrete Prüfungsform lohnt sich zusätzlich gezieltes Üben der dort genannten Aufgabentypen.

Tier 1 — zuerst, auswendig sitzen

Größte/am stärksten betonte Blöcke im Original bzw. mehrfach in ub/ aufgegriffen.

  • Entwurfsmuster (Proxy, Befehlsmuster, Abstrakte Fabrik, Strategie, Beobachter, Adapter, Brücke, Fassade, Composite) — im Original explizit der größte Block auf dem A3-Blatt, in uebersicht.txt aber nur stichpunktartig — genau deswegen Lücke, die durch VL-Folien geschlossen werden muss. → Summary · Test
  • Taxonomie „Die Welt der Softwaretechnik“ (Produkt-/Prozessprobleme, technische/methodische Lösungsansätze) — mit 43 Zeilen der mit Abstand längste zusammenhängende Block in uebersicht.txt, dient als Ordnungsrahmen für fast alle anderen Themen. → Summary · Test
  • Analytische vs. konstruktive Qualitätssicherung (dynamisch: Defekt-/Benutzbarkeits-/Last-/Leistungs-/Stress-/Akzeptanztest; statisch: manuell/automatisch; konstruktiv: Test-/Durchsichtmgmt, Prozessmgmt, Risikomgmt) — in uebersicht.txt an zwei Stellen behandelt (Zeile 128 + 296) und deckt gleich zwei ub-Übungen ab (10 + 11) — überdurchschnittliches Gewicht. → Summary QS · Test / Summary Konstr. QS · Test
  • Testarten: Black-Box vs. White-Box (Äquivalenzklassen, C0/C1/C2-Überdeckung, Zweigüberdeckung) — konkrete Beispiele im Original (Dreieck-Beispiel) deuten auf Rechenaufgaben in der Klausur hin, nicht nur Definitionsfragen. → Summary · Test
  • Prozessmodelle: Wasserfallmodell (8 Phasen + Schwächen), iterative Modelle (Prototyp/Inkrementell/Iterativ inkl. Scrum/XP), Spiralmodell, konventionell vs. agil, strikte vs. agile Modelle im Vergleich — breitester Themenblock am Ende von uebersicht.txt, klassischer Vergleichs-/Einordnungsstoff für Klausurfragen. → Summary · Test

Tier 2 — solide Grundlagen, sicher abfragbar

Kernbegriffe, die in jeder Klausur als Definitions- oder Anwendungsfrage auftauchen können.

  • UML-Grundlagen (Sichtbarkeiten, Objektmodellierung) & Anwendungsfall-Template (Hauptakteur, Vorbedingung, Mindestzusicherung, Erweiterungen) → UML · Test / Usecases · Test
  • OCL (Einstieg + iterate-Konstrukt) & Design by Contract (Vorbedingung/Nachbedingung/Invariante) → Summary · Test
  • Arten von Anforderungen (funktional/nichtfunktional/Sicherheit/Einschränkung) + Validierung vs. Verifizierung → Summary · Test
  • Methoden der Anforderungserhebung (Introspection, Interviews, Group Elicitation, ...) → Summary · Test
  • Architekturstile (Client/Server, Mehrschicht, Ereignisgesteuert, Datenflussnetze, Web) — Originalnotiz „dickes Ding“ → aufwendig, aber jede Ausprägung einzeln merken → Summary · Test
  • Modularisierung, Information Hiding, Module beurteilen (Kriterien) → Summary · Test

Tier 3 — ergänzend, wenn Zeit bleibt

Wird meist nur mit Einzelfragen abgeprüft, aber schnell nachzuholen.

  • Projektmanagement: 2 Stile (planend-leitend vs. agil-selbstorganisiert), Aufgabenzerlegung, Risikomanagement-Stile, Netzplan → Summary · Test
  • Wiederverwendung: Prinzipien (Universalität, Abwägung), Effekt auf Qualität/Produktivität/Risiko → Summary · Test
  • Anwendungs- vs. technische Domäne, Anwendungsdomänen-/Lösungsdomänenklasse, Analysten vs. Entwerfer → Summary · Test
  • Dynamische Modellierung / Aktivitätsdiagramm-Notation (im Original nur [GRAFIK] — Notation separat üben) → Summary · Test
